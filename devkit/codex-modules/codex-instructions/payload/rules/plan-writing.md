# Plan writing

Read the target files before describing how they behave. Search for existing patterns before adding new artifacts. If a plan claims runtime behavior, cite a command that observed it; otherwise mark the claim as an inference.

Scale review to the change: a one-file local edit may need no separate gate; shared contracts need an impact note; architectural changes need research and a design that identifies open questions. A plan should name the files read, relevant commands run, design choices, and implementation order.
